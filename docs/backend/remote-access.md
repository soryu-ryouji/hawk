# 远程访问设计

> 远程访问是可选的云能力：hawk 仓库开源客户端（remote 模块）与协议契约；云端服务为独立实现（商业信息不在本仓库）。
> 接口契约见 [remote-protocol.md](remote-protocol.md)。

## 目标与非目标

**目标**：在客户端配置接入信息（信令地址 + 访问密钥）后，查看自己其他在线设备，远程浏览对方设备上的素材库（只读）。

**非目标**（v1 不做）：

- 远程写入素材库（修改标签、导入素材等）——远程一律只读，写入仍在本机完成
- 多人协作 / 共享库给他人——设备只属于同一账号
- 移动端查看器——后续迭代，协议不为此预留特殊设计

## 总体架构

```text
┌────────────────────── 云端（hawk-remote-server 仓库，闭源）──────────────────────┐
│ 账户 + 信令服务（Rust/axum + PostgreSQL）                                        │
│   · 账户与密钥（用户数据，持久化）                                                │
│   · 设备注册、心跳、在线状态（内存态，TTL 过期）                                   │
│   · 会话编排：下发直连参数，或签发中继票据                                         │
│                                                                                 │
│ 中继服务（quinn，无状态 UDP 转发，可选 TCP 帧模式）                                │
│   · 校验账户服务签发的票据（HMAC，不查库）                                        │
│   · 在会话双方间逐包转发，计量字节数，异步上报账户服务                              │
└───────────────▲─────────────────────────────▲──────────────────────────────────┘
        HTTPS + WSS 控制面              QUIC 数据面（P2P 直连 / 经中继转发）
                 │                              │
┌────────────────┴───────────┐    ┌─────────────┴──────────────────┐
│ 设备 A（素材库所在机）        │    │ 设备 B（查看方）                  │
│ hawk-app                    │    │ hawk-app                        │
│  ├ hawk-server（环回）       │    │  ├ hawk-server（环回）           │
│  └ remote 模块              │◄──►│  └ remote 模块                  │
│     · 心跳 / UPnP 端口映射   │    │     · 设备列表 / 发起会话          │
│     · QUIC 隧道端 → 127.0.0.1│    │     · 本地代理 127.0.0.1:27374  │
│        （注入远端只读 token） │    │        ▲ 浏览器加载 web 查看器    │
└─────────────────────────────┘    └─────────┴──────────────────────┘
```

## 组件职责

### 云端 hawk-remote-server（闭源，独立仓库）

- 与 hawk 仓库**零代码共享**：不含任何 hawk 代码，只实现协议契约。AGPL §13 不适用于独立作品
- v1 一个仓库两个二进制：`account-server`（账户+信令）与 `relay-server`（中继）；中继以后按节点扩展部署，不需要拆仓库
- 账户服务与中继节点之间通过内网 + 共享密钥通信（用量上报、票据密钥分发）

### hawk-server remote 模块（feature 门控，随 AGPL 开源）

客户端侧全部能力，编译进 hawk-server 二进制，由 `remote` Cargo feature 门控（默认关闭）：

- 信令客户端：设备注册、周期心跳、WSS 控制通道
- 可达性：UPnP/NAT-PMP 端口映射（igd），公网 IP 探测
- 数据面：QUIC 隧道端（A 侧：注入远端只读 token 后转发到 127.0.0.1:27371；B 侧：本地代理端口）
- 中继客户端：UDP 直连中继 / TCP 帧模式

运行时配置由 Electron 主进程经 CLI/env 传入（信令地址、访问密钥），不写入 config.toml。凭据与证书持久化在 `.hawk/remote/`（本地专用目录，与 `trash/` 同类，不参与同步）。

### hawk-app 云端 UI（构建期门控）

接入配置页（URL + KEY）、设备列表、连接流程、错误提示全部收敛在 `src/remote/` 目录，经构建期常量 `HAWK_REMOTE` 接入路由。默认构建树摇后 bundle 中无任何云端 UI。web 查看器本身不含账户 UI——远程查看时它只访问本机代理端口，与局域网场景同一个构建产物。

## 关键设计决策

**1. 数据面从第一天用 QUIC（quinn），P2P 与中继同一传输**

避免"先 TCP 直连、后为中继/打洞重写隧道"的返工。QUIC 自带多路复用、TLS 1.3 端到端加密、抗 NAT 重绑定。中继只逐包转发加密数据报，看不到素材内容；中继被攻破也无数据泄露。

**2. 远程访问对 hawk-server 本体零侵入**

A 侧隧道端接 127.0.0.1:27371，复用现有 REST API 与 web 查看器，OpenAPI 契约、SSE、缩略图端点全部原样可用。鉴权上 A 侧隧道端向环回请求注入"远端只读 token"（启动时经 env 传入的第三种 token，只读级别）——查看方 B 全程不接触任何 token，云端也接触不到。远程访问不要求启用 `[web]` 局域网配置，两者相互独立。

**3. 协议契约先行，零代码共享**

hawk 与云端服务之间的契约是 [remote-protocol.md](remote-protocol.md)（文档 + OpenAPI + WSS 消息格式），放在 hawk 仓库公开。闭源仓库是契约的一个实现；自托管用户可以照协议自行实现信令服务。两端靠契约测试对齐，不靠共享 crate（共享 crate 会使闭源服务链接 AGPL 代码而必须开源）。

**4. 客户端最小知识：URL + KEY，无登录**

客户端配置只有两项：信令地址 URL 与访问密钥 KEY（官方构建内置 URL，用户只粘贴 KEY；自托管构建两个都填）。协议无登录端点、无会话令牌；服务端自行决定 KEY 的判定逻辑（密钥表、固定密钥、任意放行均可）。客户端对所有错误的处理一致：直接展示服务端返回的 message；引导信息（如重签密钥的页面 URL）由服务端在 message 中给出，客户端不内置任何服务方的指引地址，用第三方/自托管服务时不会误导向官方页面。详见协议文档的「HTTP 状态码」一节。

**5. 会话认证在 QUIC 层，隧道内 HTTP 无鉴权**

设备自签名证书指纹在信令服务登记（TOFU），会话建立时经信令交换指纹，QUIC 对端以指纹钉扎验证。会话建立后，隧道内的 HTTP 请求由 A 侧隧道端统一注入远端只读 token。B 侧本地代理端口按会话生成随机 token，web 查看器以 `?token=` 携带，代理响应不带 CORS 头（沿用 hawk 本体的本地防护模型）。

## 连接建立流程

### 直连模式（阶段 1）

```text
B 配置接入 → 拉取设备列表（A 在线 + 心跳携带可达性信息）
B 发起会话（mode=direct）
信令服务：A 心跳上报过"公网 IP + UPnP 映射成功"？
  ├─ 是 → 创建会话，经 WSS 推送给 A：session_request
  │        A 校验会话（自动接受，设备级开关 allow_remote 控制）→ 回 accept
  │        信令服务向 B 返回 A 的 {public_ip, mapped_port, fingerprint}
  │        B 建立到 A 的 QUIC 连接（指纹钉扎）
  └─ 否 → 会话状态 unreachable，B 的 UI 提示：
          "当前网络不支持直连，可走中继" → 转入中继流程
```

直连超时（默认 30s）同样回落到中继提示。连接成功后 B 的 app 打开本地代理 URL，浏览器加载 A 的 web 查看器。

### 中继模式（阶段 2）

```text
B 发起会话（mode=relay）
信令服务：校验访问资格与中继额度（服务端规则，拒绝时 401）→ 签发两张中继票据（role=a/b，含配额、有效期）
双方经各自 WSS 通道收到票据 → 各自连接中继节点（UDP；UDP 被封锁时 TCP 帧模式）
中继验签 → 配对双方地址 → 逐包转发（QUIC 在 A↔B 之间端到端建立，中继只搬运）
会话期间中继计量字节数 → 周期上报账户服务 → 额度用尽断流
```

## 安全模型

| 环节     | 措施                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 控制面   | HTTPS/WSS，access_key 为 256-bit 随机值，服务端只存哈希                               |
| 数据面   | QUIC TLS 1.3 端到端加密，证书指纹经信令交换 + 钉扎；中继不可读内容                    |
| 本地防护 | 远端只读 token 只在 A 进程内存（env 注入，不落盘）；B 侧代理会话级随机 token、无 CORS |
| 中继票据 | HMAC 签名，绑定会话与配额，短有效期（建立窗口 10 分钟），防重放靠 source addr 绑定    |
| 凭据存储 | 访问密钥、device_id、证书私钥存 `.hawk/remote/`（本地专用）                           |

## 分发与开源边界

- hawk 仓库内的 remote 模块与云端 UI 随 AGPL 开源——分发含它们的二进制本就要求提供对应源码，放公开仓库是最直接的履行方式
- 社区构建 = 干净本地版：Cargo `remote` feature 默认关闭 + 前端 `HAWK_REMOTE` 默认 false，编译产物中物理上不存在云端代码与 UI；CI 增加产物清洁性检查（社区构建中搜不到 remote 标识字符串）
- 官方构建：`cargo build --features remote` + `vite build --define HAWK_REMOTE=true`，CI 双矩阵测试
- 云端服务闭源、只部署在自己的基础设施上，从不随客户端分发

## 分级落地计划

| 阶段 | 内容                                                                                    | 验收标准                                                                 |
| ---- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1    | 云端服务（账户/密钥/信令，实现协议）+ hawk 侧 remote 模块（注册/心跳/直连）+ 双构建体系 | 公网 IP 用户端到端远程查看可用；社区构建产物无云端代码；401 访问控制可用 |
| 2    | 中继服务（票据 + 字节计量 + TCP 帧模式，额度规则为服务端内部逻辑）                      | 直连失败自动引导中继；额度计量与超配额断流正确                           |
| 3    | QUIC 打洞（免端口映射 P2P）                                                             | 视阶段 1 直连成功率数据决定是否投入                                      |
