# 感知哈希相似图片查找

> 相同图片的 dHash + RGB 近重复检索。可选 DINOv2 构图检索见 [视觉扩展与相似构图](vision-search.md)。

## 目标与边界

提供**视觉近重复**查找：同一张图片经过缩放、格式转换、重新压缩或轻微编辑后，仍能被找到并按相似程度排序。

本期不做语义相似（不同照片但主体相同）。感知哈希对大幅裁剪、旋转、镜像、不同拍摄角度不可靠；这些场景需要后续的向量模型方案，不能靠调大阈值代替。

## 算法与常量

- 实现库：`image_hasher`
- 预处理：灰度 → 稳定 Lanczos3 缩放至 9×8
- 哈希算法：Gradient（dHash），逐行比较相邻像素明暗，输出 8×8 = 64 位
- 距离：两个 64 位值 XOR 后的置位数（汉明距离，0–64，越小越相似）
- 候选复核：同一解码过程生成 8×8 RGB 平均色网格，以归一化 RMS 比较颜色与空间布局
- 算法版本：`PHASH_VERSION = 3`（v1 的 DCT+Mean 会被直流分量主导；v2 改用 Gradient；v3 增加 RGB 复核，旧值自动重算）
- 接口、存储字段和常量沿用 `phash` 命名，当前实际哈希算法为 dHash
- 单图查询：相似度滑块 `0–100` 映射最大距离 `20–0`，默认中间值 `50` 对应 `0–10`；用户设置经 localStorage 持久化

不使用 `image_hasher` 标记为不稳定的 resize 特性。参数或算法变化时必须递增版本，旧版本由维护任务重算。

## 计算与 SQLite 存储

dHash 与 RGB 网格是内容的纯函数，与调色板、宽高一起存入 `.hawk/metadata.db`，不进入库外缓存，也不写 TOML：

```text
items.phash          TEXT     # 16 位小写 hex；NULL 表示非图像负缓存或尚未计算（由 version 区分）
items.phash_version  INTEGER  # 0 = 尚未计算；3 = 当前特征版本
items.rgb_grid       TEXT     # 8×8×3 平均色，384 位小写 hex
```

内存中使用整数与定长字节数组，避免查询时反复解析十六进制。非图像写入 `version=3, value=None` 负缓存，防止每次启动重复探测；暂时解码失败保持未计算，后续维护重试。

```text
扫描/增量入库/周期维护
  → 单次解码原图
  → 同时产出 调色板 + dHash + RGB 网格 + 缩略图（按需）+ 宽高
  → worker 经 JobSender 回流
  → 每 500 条或滞留 2s 批量写 SQLite
  → 合并 items.updated 通知客户端
```

老库只增量增加 `phash` / `phash_version` / `rgb_grid` 列，已有 SQLite 标签、评分、备注和位置不变；不读取、不迁移旧 TOML 元数据。周期维护间隔由 `HAWK_MAINTENANCE_INTERVAL` 控制（默认 60s，0 关闭）。

## 查询契约

复用 `POST /api/v1/item/list` 与 `POST /api/v1/item/skeleton`，新增请求字段：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `similar_to` | string | 源 item id（内容哈希） |
| `max_distance` | number | 最大汉明距离，0–64；缺省 5 |
| `order_by` | string | 设为 `similarity` 时按距离排序，必须同时提供 `similar_to` |
| `order` | string | 前端固定 `asc`，即最相似优先 |

响应中的 `Item` 和骨架条目在相似查询时增加可选 `similarity_distance`。其他查询不返回该字段。

- 源图必须存在、当前用户可见且已有当前版本 dHash 与 RGB 网格；源图被锁返回 403，未分析返回 400 和明确提示
- 过滤与其他查询条件保持 AND 语义，锁排除、位置展开和回收站规则不变
- 两阶段过滤：dHash 距离不超过 `max_distance`，且 RGB RMS 不超过 `0.06 + 0.003 × max_distance`；避免灰度哈希相近但颜色/布局不同的误报
- 源图在阈值内且属于当前结果范围时也会出现在结果中，差异值为 0
- `item/list` 与 `item/skeleton` 使用同一过滤和确定性排序，继续支持虚拟网格按 offset 取详情

## 设置中的重复图片管理

「设置 → 存储 → 重复图片」提供两个独立扫描标签：

- **相似图片**：不同 item 的感知哈希近重复组；Eagle 式相似度滑块 0–100 映射最大距离 20–0（越右越严格），默认 75 对应 0–5，拖动松开后重新扫描。
- **相同内容**：同一 item/hash 下存在多个非回收站位置，只列出位置数大于 1 的组。

`POST /api/v1/item/duplicates` 分页返回组及每个位置的 Item、文件大小、像素和差异值，admin 限定。每个位置独立复选，跨页保留选择；默认不选中，不做“最佳版本”自动保留。

删除只按 `id + path` 调 `item/delete` 移入回收站，不调用整 item 删除；操作前经应用内 `ConfirmDialog` 二次确认。最后库内位置被移动后 item 也进入回收站，仍可恢复；部分失败保留选中并显示成功/失败计数。

### 分组索引

相似扫描采用 **4×16bit 分带索引 + 完整距离复核 + 并查集**：

- 距离 ≤5 时至少一个 16 位段距离 ≤1，距离 ≤10 时至少一段距离 ≤2；枚举对应变体即可保证不漏候选，再做完整汉明距离过滤。
- dHash 相同的不同 item 先按 bits 预分组，避免 BK-tree 对距离 0 元素的忽略行为；候选合并前同样执行 RGB 复核。
- 大于 10 的非常用阈值回退到通用 BK-tree，避免分带变体组合爆炸。
- 正确性测试将分带路径和 BK-tree 回退都与暴力分组结果对比，不依赖性能推测正确性。

## 前端交互

- 网格右键与预览菜单只提供“查找图片”单入口；这是读操作，viewer / importer 也可使用
- 非图片或宽高未解析的素材不显示入口；源图尚未完成分析时由 API 提示稍后重试
- 结果在独立 SimilarImageDialog 弹窗展示，不改变主列表视图、筛选条件或浏览历史；弹窗使用同一套 dHash + RGB 算法，仅通过相似度滑块调整阈值（默认中间值 50=0–10），松开后持久化并重查
- 弹窗展示源图、结果数、差异值与分页（每页 60 项），固定按距离升序，包含加载、错误、空态与 Esc/遮罩关闭；结果卡片右键可关闭弹窗并跳转到对应文件夹视图
- 图片仍按低带宽策略加载：网格 512、广域网预览 1024，放大才取原图

## 验证

- dHash：重复计算一致、缩放/JPEG 重压缩距离较小、不同画面可区分
- RGB 网格：缩放/重压缩保持接近；灰度化或颜色显著不同的候选被排除；hex 跨重启往返一致
- SQLite：dHash/RGB 跨重启保留；v1 数据加列后保留；非图像负缓存
- 查询：距离升序、阈值过滤、骨架同序、未分析/非法排序错误
- 前端：相似请求参数、阈值历史、预览菜单入口、差异值展示

## 性能观测

当前为内存线性扫描，和颜色检索同一量级。仓库内 `similarity_large_index_benchmark` 覆盖 100,000 个条目（其中 10,000 个命中），本机 debug 实测过滤与排序约 **18.7ms**；该值只作量级参考，不承诺所有设备一致。

重复扫描 `similar_groups_large_benchmark` 覆盖同样的 100,000 个随机 pHash：通用 BK-tree 约 **69s**，分带索引优化后约 **2.27s**（本机 debug）。这证明默认阈值下不需要 O(n²) 两两比较；高阈值回退路径只用于非常用场景。

若真实库证明其成为瓶颈，再评估多哈希或向量索引；当前不引入独立相似度数据库。
